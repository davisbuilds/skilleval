# Roadmap

Build a useful evaluator for independently supplied skills. The first comparison
is explicit skill ON/OFF on relevant tasks, measuring task quality and outcomes
alongside actual consumption. The [vision](VISION.md) owns the principles;
[backlog](BACKLOG.md) owns concrete unresolved work.

## Current foundation

The CLI supports immutable captures, task/environment packages, native Codex
execution, review/repair/document artifacts, independent offline checks, and
static or investigative semantic judgments. Judges and synthesis can select
[Claude Code subscription / Opus](../system/CLAUDE-JUDGES.md); task agents retain
the Codex route. Development studies freeze paired
inputs and budgets, preserve every attempt, and produce readable artifact and
usage comparisons. [Task packages](../system/TASKS.md) and
[study orchestration](../system/STUDIES.md) own those contracts.
Operator acceptance maps now bind declared requirements to exact probe fields,
semantic questions, controls and coverage gaps. Mapped plans freeze their identities
without exposing them to solvers. [Measurement design](MEASUREMENT.md) owns source
work selection and validation; structural map checks do not establish validity.

Runtime controls cover bounded filesystem/network behavior, task fidelity,
termination, recovery, and cleanup on the tested smolvm route. Admission is tied
to exact execution identities. Native context controls now exercise production
OFF/ON/fresh OFF, declared defaults, contamination detection and preflight refusal;
their [scope](../system/NATIVE.md#operator-state-and-effective-context) remains
separate from scored admission. Judge controls cover authored labels and selected
repeat/order/perturbation cases. The [solver boundary](../system/TASK-PRESENTATION.md)
now separates filesystem/process authority and denies guest management transport,
with working native task controls. App-server now declares external enforcement
and produces restricted-network wording in captured requests. Generic filesystem
wording remains an upstream limitation. Representative task/image coverage,
independent semantic audit and scored-study admission
remain pending. Development workflows can progress while those gates
are open; they cannot become scored trials by relabeling their results.

Run data now has a [durable storage layout](../system/STORAGE.md) outside
implementation checkouts. Native runs retain guest-local session rollouts with
explicit reasoning-summary coverage; guarded staging cleanup preserves replay
evidence. Retained historical locators stay in place until supported relocation
exists; obsolete cohorts can be deliberately retired with a dependency check and
compact receipt. A private index separates active evidence from references and
retired work. Backup and automatic expiry remain operator decisions.

The [source register](SOURCES.md) records adopted ideas and implementation:
SkillsBench/Harbor packaging, Tessl fixtures and explicit variants,
Anthropic/Engram assessment patterns, gstack's separation of validity and benefit,
and the adapted OpenBench gateway. External skills remain experimental inputs.

## Now: research capability and a relevant inquiry

The next selected skill family is direct research. Qualify the opt-in
[native web-search and research-judge route](../system/RESEARCH.md), then choose
an actual unresolved inquiry for an explicit `deep-research` ON/OFF pilot. Topic
selection and task-specific criteria remain open. Start with one faithful skill
and equal retrieval access; measure supported, useful answers alongside total
agent consumption. Native hosted-search metadata and model-authored verification
notes have different evidence strength from retained source passages.

Research-architect commissioning can later compare prompts through fresh,
identically configured researchers. Assessment of supplied reports is another
separate comparison. Interactive question formation needs the backlogged Q&A
capability; a noninteractive drafting task cannot establish that benefit.

The earlier [operational-metrics specification pilot](../../examples/document/operational-metrics/README.md)
remains development evidence, including both artifacts, downstream browser/API
observations, an interrupted implementation and incomplete accounting. It does
not establish a skill advantage or an efficiency winner. Its document collection,
fresh-agent handoffs, requirement-level judgments and linked-stage accounting are
reusable infrastructure. Original evidence and its stated limits remain intact.

1. **Develop useful acceptance criteria through ordinary work.** Exploratory pairs
   can start from an original brief, faithful context and provisional criteria/gaps.
   Use `mapped-acceptance-v1` when those criteria are ready to freeze.
   The retrospective completed-session map exposes uncovered lifecycle cases and
   grader evidence loss; it does not upgrade the original six-probe results.
   The corrected-packet audit and retained-pair semantic reassessment are complete
   as development evidence. Seek independent domain review of scope and brief
   sufficiency before scored or general effectiveness claims; exploratory work can
   continue with those limits declared. Include a blind alternative implementation
   where it resolves a consequential uncertainty. Preserve the
   qualified external-enforcement route and track its documented native wording
   limits. Use ordinary work briefs; review
   actual instructions, accessible files/history, skill resources and tool outputs
   for evaluation disclosures. Neutral labels alone do not satisfy this boundary.
2. **Broaden the skill-relevant population.** Start with the engineering source
   priorities in the [candidate register](PILOT-CANDIDATES.md#current-selection-direction)
   and concrete work maintainers actually delegate. Discuss task briefs, skill fit,
   deliverables and independent outcome checks before capturing the next cases.
   Start with one independently usable skill and its required resources; defer
   packages that require a larger multi-skill or orchestration workflow.
   The first selected engineering slice pairs the completed-session repair with
   Matt Pocock's diagnosing-bugs skill. Its source and full skill closure are
   captured with [environment and checker controls](../../examples/repair/completed-sessions/environment.md).
   Its revised disposable application home is qualified; ordinary test exceptions
   and task-specific audit limits remain. The
   [debugging expansion shortlist](PILOT-CANDIDATES.md#debugging-expansion-shortlist)
   retains fetchmd and Promptfoo candidates for later consideration, with Dojo
   reserved. They are not the next selected task and still need capture and
   executable validation.
   Preserve selection reasons and exclusions. Do not retain
   only vanilla failures or wins for the skill.
3. **Audit representative judgments with corrected evidence.** Review actual
   artifacts, source support, novel findings, alternative solutions, checker
   defects, and disagreements. `execution-context-v3` now retains outputless command
   completions, ordinary application-home source output and observable edit chronology.
   The supplementary lifecycle controls cover cached handover and reader limits
   under a new task identity. Fresh investigative judgments now assess both
   retained repairs with those observations, and a separate automated source audit
   corroborates their concrete findings. The new report explicitly selects those
   records while retaining earlier judgments and all judge invocation costs.
   Both repairs miss history preservation; investigation also exposed a new
   baseline-relative handover regression beyond the supplied checks. Supported
   test outcomes remain distinct from contradicted broad completion claims.
   Independent human/domain review remains pending; same-family agreement does
   not establish reliability. Reuse retained solver artifacts in fresh evidence
   generations, without counting related probes or overlapping criteria as
   independent outcomes.
   Tiny authored label controls test the grader machinery; their difficulty does
   not define the task population. The earlier tiny-control human audit is no
   longer an active request or prerequisite after the task realignment; preserve
   its historical records and build new audits around the selected real tasks.
4. **Close task-specific environment gaps.** Use the unprivileged solver profile
   and required tools. Reuse applicable environment and context evidence, and
   revalidate changed boundaries or consequential gaps. Verify the actual harness
   context excludes operator instructions and machine state, with contamination
   canaries and working positive controls. Keep baseline failures,
   skipped lanes, unsupported platforms, and artifact-budget limits explicit.
   Capture corrections do not upgrade earlier attempts.

Task design, exploratory comparisons and judgment audit can progress together.
Preserve the visibility boundary and report acceptance gaps without treating an
exploratory pair as an audited effect estimate. Add an
adapter when the selected task requires it, rather than expanding harnesses or
infrastructure in advance.
Maintain the public foundation and [hosted checks](GIT_HISTORY_POLICY.md) as this
work develops; publication is complete and does not qualify evaluation outcomes.

## Next: repeated, interpretable comparisons

Freeze task selection, exposure history, complete skill bytes, model/harness,
environment, budgets, primary outcomes, retry policy, and assessment selection
before dispatch. Keep ordinary context and capabilities comparable and vary only
the declared treatment. Randomize adjacent matched runs and retain unsuccessful
attempts and missing observations.

Define the sampling frame and keep task/rubric development separate from held-out
effect estimation. Use pilot variance, the smallest useful effect and desired
precision to choose independent tasks and repetitions; six related probes are
not six tasks. Report paired quality, failure, token, cost, and timing differences with
uncertainty that respects task/repository clustering. Judge spend stays separate;
conditional API-equivalent estimates are not observed subscription charges.
Inconclusive or saturated comparisons are useful outcomes.

Scored dispatch requires both applicable full-workload environment evidence and
independently supported grader reliability. A bounded runtime seal, parseable
judgment, model agreement, or successful skill read cannot satisfy those gates.

The [local results view](../system/RESULTS.md) now presents selected synthesis,
evidence excerpts, agent follow-ups and qualified unknowns, with separately saved
answers only for material human questions. The explicit
[native synthesis pipeline](../system/SYNTHESIS.md) records that investigation
over selected handoff evidence, with canonical accounting supplied by replayed
receipts. Automatic follow-through is deferred until repeated use warrants it.
The summary remains useful when no human action is required.
Use [task-scoped readiness](../system/TASKS.md#readiness-reuse-and-invalidation)
to reuse completed environment observations as briefs, grading criteria and
reporting evolve. Opt into independent lane validation to rerun only checks whose
execution conditions changed, retaining the initial cost of a fresh VM per lane. Current
parsers and expectations replay retained evidence. Frozen study plans still bind
full identities. Use dispatch/lifecycle phase timings and observed invalidation
causes to choose further launch optimizations without weakening runtime boundaries.

## Later

Expand to multi-skill/workflow treatments, natural discovery and the pi harness.
Protected holdouts, additional task families, and automation follow the same
evidence and accounting contracts.
A universal leaderboard and automatic skill optimization are outside the initial
scope.

## Development observations informing this sequence

These are maintainer-observed development results through 2026-10-29. Raw runs
remain outside the public source tree; this summary is not a reproducible public
benchmark release or an effectiveness claim.

- The repair capture reproduces 2,006 baseline and 2,010 reference tests, each with
  two declared root-sensitive failures and eight skips. This restored missing
  context/history while leaving environment coverage gaps visible. See the
  [task environment record](../../examples/repair/receipt-admission/environment.md).
- Semantic investigation found an observation-fixture defect in the first repair
  comparison. Corrected checks accepted both repairs; original workers, results,
  and judgments remain separate. The earlier apparent difference was not a valid
  functional advantage.
- Two distinct supported writing drafts and a format-valid false-cost claim
  matched ten prespecified authored judge expectations. One subsequent ON/OFF
  pair passed mechanical checks and all four document criteria in both arms.
  ON read the skill and used 98,644 total tokens and 49.10 agent seconds; OFF used
  58,335 tokens and 38.04 seconds. This rubric recorded no quality advantage in
  that pair; independent audit and repeat evidence remain missing.

These observations support better fixtures, representative task selection, and
independent audit as the next work. Detailed implementation history remains in Git.
